# 平台与封面

zh-longform 的发布、平台适配、封面和质检规范。下文命令里的 `<SKILL>` 指本 Skill 的安装目录，比如 `~/.claude/skills/zh-longform`；命令都在写作项目的根目录运行。

正文怎么写见 [写作规范](写作规范.md)。本文件只管写完以后的事：派生各平台版本、做封面、跑质检和发布。

## 发哪几个平台

每篇文章在 frontmatter 里用 `platforms` 写明要发哪几端：

```yaml
platforms: [x]                 # 默认，只发 X
platforms: [x, xhs]            # 加发小红书
platforms: [x, xhs, wechat]    # 三端都发
```

只做列出的平台版本，没列的不做。质检脚本按这个字段决定查什么：

- 列了 `xhs`：必须有 `文章_小红书版.md` 和 `caption_小红书版.md`，并对小红书版按严格模式做敏感词和外链检查。
- 列了 `wechat`：必须有 `文章.html`，导流话术按严格模式阻断。
- 没列的平台，跳过对应检查。
- 没写 `platforms` 的旧文章，按原来的方式检查，结果不变。

封面不受这个字段影响。X 的 `cover.png` 是公众号版的副本，两张封面又出自同一张母稿，所以每篇都照常出两张。

## 一、交付质检

### 1. 命令

```bash
# 单篇标准检查，附带小红书与公众号合规提示
<SKILL>/scripts/verify_article.sh "05_待发表/<主题>"

# 小红书严格模式：外链和敏感词直接阻断，优先检查 文章_小红书版.md
<SKILL>/scripts/verify_article.sh --xhs "05_待发表/<主题>"

# 公众号严格模式：导流话术直接阻断
<SKILL>/scripts/verify_article.sh --wechat "05_待发表/<主题>"

# 强制检查双尺寸封面，用于旧文章升级
<SKILL>/scripts/verify_article.sh --covers "05_待发表/<主题>"

# 全库扫描，可与 --xhs 或 --wechat 组合
<SKILL>/scripts/verify_article.sh --all

# 只查封面文件
python3 <SKILL>/scripts/verify_covers.py "05_待发表/<主题>"
```

出现红色错误先修好再交付。脚本只做机器能判断的检查，事实核查、译名、视觉质量和独立审读不能拿脚本的退出码代替。

### 2. 脚本检查的内容

1. `文章.md`、`caption.md` 和独立的 `审读.md` 都存在，审读没有未解决的退回结论。
2. frontmatter `title`、正文 H1 和 caption 标题逐字一致。
3. 图片全部是有效的相对路径 `imgs/...`，没有绝对路径和 HTTP 外链。
4. 已知错字与赘字，比如「在在」「的的」「映到」「填色」。
5. 没有弯引号“”。
6. 盘古之白，已排除代码块、行内代码、URL 和 Markdown 链接。
7. 「三件事」「四个要点」这类说法和后面列表的项数一致。
8. 「预计」「截至 YYYY-MM-DD」这类时效说法，提醒发布前复核。
9. 小红书敏感词与外链，词表见第三节。
10. 公众号导流话术、结构化表格和图注出处，见第四节。
11. 输出 X Article 配图插入对照表。
12. 声明了 `cover_style` 的文章自动检查双封面，见第五节。

写作规范里的其他要求，比如外文对照、参考来源、算账、正文配图只用物证、名词排查，由独立审读负责检查。

### 3. 发布前 5 分钟复核

涉及 AI 模型、API 计费或软件界面的教程，在发布当天复核一遍：

- [ ] 软件或平台最近一周有没有破坏性更新，比如菜单位置变了、版本升级了。
- [ ] 文中的模型 ID 和价格是否仍然有效。
- [ ] 正文里的时效说法已更新为当天或最新核验日期。

### 4. 交付回复

交付时直接给出正文、配文、小红书封面和公众号封面的文件链接。缺任何一张必交封面，就标「封面未完成」，不能说整篇完整交付。

## 二、X Article

每篇都有。资产：`文章.md` 和 `caption.md`。caption 写 1~3 段，讲清核心主张和读者能得到什么，标题与正文一致，不写正文没有的事实。

X 的网页编辑器不会自动上传 Markdown 里的相对路径图片，发布分三步：

1. 复制 `文章.md` 正文，去掉 frontmatter 和 Obsidian 注释 `%%`，粘贴进编辑器。
2. 按 `verify_article.sh` 输出的配图插入对照表，在对应小标题下拖入图片。
3. 推文框粘贴 `caption.md`，把 `imgs/cover.png` 设为长文封面。

## 三、小红书

`platforms` 列了 `xhs` 才做。资产：`文章_小红书版.md`、`caption_小红书版.md`、`imgs/cover-xhs.png`（1440 × 2400）。正文里嵌入封面时引用竖版。

### 1. 小红书版允许的例外

为了适应手机阅读和平台推荐，小红书版可以偏离写作规范的以下几条，其他规则照旧：

- 标题不超过 20 个汉字，可以用单个问句，比如《施乐为什么会输给苹果？》。依然不能用感叹号、反问三连和震惊体。小红书版有自己的标题时，`caption_小红书版.md` 与 `文章_小红书版.md` 保持一致。
- 每段 2~3 句，手机上不超过 3~4 行。
- 小节和转折处可以用 🏠、💣、💻、💡、💬 这类 emoji 做标记。
- 核心数字和结论可以轻度加粗。
- 结尾可以设一个具体的讨论话题，比如「你觉得做投资，直觉和逻辑哪个更重要？评论区聊聊👇」。
- 话题标签 3~4 个，只留和正文实体最相关的，比如 `#乔布斯 #施乐 #商业思维`，不堆 `#深度思考` 这类泛标签。

### 2. 审核机制

- **静默拦截**：笔记发布后作者自己能看到，别人主页看不到，搜标题搜不到，也没有违规通知，通常是第一道机审命中了敏感词。
- **两层审核**：基础层拦截涉黄、涉毒和严重违法内容。薯条加热是付费推广，按商业化规范从严审核，时政军事、无资质医疗、宗教和极端负面内容一律不过。能过薯条审核，说明全网分发基本安全。
- **图片也会被扫描**：OCR 会逐字识别封面、长图和卡片里的文字，标准和正文一样。
- **外链零容忍**：正文、图注和评论区出现 `http://` 或 `https://` 开头的链接，按违规导流处理。

### 4. 防止被判定为洗稿

文字已经处理干净，发布后还是搜不到、阅读量只有个位数，通常是命中了同质化比对：

- 不按时间线复述公众熟知的事件。网上有大量同类图书和通稿，流水账会被当成搬运。
- 只聚焦一个商业机制或认知反常，用自己的话给出判断，开头直接说结论。比如把一段大历史改写成「手握王牌的大公司为什么输给创业者」。
- 开头要有博主本人的视角，比如「最近翻完 Thrive Capital 创始人的万字长文，里面有一个细节让我琢磨了很久……」，不写第三人称通稿。

### 5. 发布与验证

1. 发布前检查三件事：正文已替换敏感词，图片里没有敏感文字，标题在 20 字以内。
2. 后台勾选「AI 辅助创作」标签。
3. 发布后 10 分钟内点「薯条推广」。提示「无法推广」或「涉及行业限制」，说明被静默拦截了，需要下架修改。能直接进入投放金额设置页，说明已经过了机审。
4. 用没有浏览记录的小号或隐身模式搜完整标题，确认已被收录。
5. 被限流或驳回时，不要在原笔记上反复修改提交，多次驳回会影响账号权重。先把原笔记设为私密，不要连续删除，换个角度重写后再发。

### 6. 轮播图

小红书的图文笔记用一组 1080 × 1440 的轮播图，版式统一为 B 版式。轮播图有两种：精简版按 `小红书图片.md` 切分重点，全文版把小红书版正文一字不删排成图，见本节末尾的「全文轮播图」。
- 一种纸色底，一种强调色。强调色按封面配色从绿、蓝、砖红、赭黄四组里选，写在 `palette`。
- 正文图和引语图左上角有章节号和一条短色条，底部左侧是系列名，右侧是页码。
- 引语图换成同色系的浅底，出处用强调色。
- 没有框、标签、emoji 和「核心结论」之类的总结句。
- 标题用宋体粗体，正文用冬青黑体，引语用宋体常规体。

只有三种卡片：封面、正文、引语。

封面卡统一做成「顶部插画 + 短标题」：

- 顶部 1080 × 760 插画条用第五节的封面母稿 `imgs/cover-source/master.png`。不写 `cover_art` 时工具自动使用这张图，只有另用别的插画时才写路径；确实不放插画时写 `cover_art: none`。插画只裁不改色，正文图和引语图不放插画。
- 用 `cover_focus` 调裁切焦点（x,y 取 0～1）。插画条是横条，方形母稿上下会被裁掉约三成，出图后要看一眼头、手和关键物件是否还在，常用值在 `0.5,0.55`～`0.5,0.62` 之间。
- 封面卡标题和副标题各须一行排下，排不下工具会报错。标题只留文章的核心短语，比如「愿我不曾虚度」，文章标题的其余部分挪到副标题。封面卡文字可以和文章标题不同，frontmatter `title`、正文 H1 和 caption 仍须逐字一致。
- 母稿还没做好时，工具会提示封面卡暂时不放插画，母稿做好后重新出图。

- 正文图：一个小标题加 1~3 段短文字，全张不超过 150 字，一张只讲一件事。
- 引语图：只放真实的一手原话，加一行出处。

断行遵守避头尾，外文人名不拆开，最后一行不留孤字。排不下时工具会报错，不会缩小字号，删减或拆成两张就行。

做法：复制 `<SKILL>/templates/小红书图片模板.md` 到文章目录，改名为 `小红书图片.md`，按小红书版正文切分好每张的文字。文章定版、审读通过，并且用户明确要出图时，再运行：

```bash
python3 <SKILL>/scripts/generate_xhs_slides.py "05_待发表/<主题>" --check   # 只检查能否排下
python3 <SKILL>/scripts/generate_xhs_slides.py "05_待发表/<主题>"           # 出图到 imgs/xhs/
```

已有图片时须加 `--replace` 才会覆盖。

切分文字时：

- 事实、数字和引文只取自小红书版正文，不新增。
- 正文里的格言式总结句不放进图。最后一张写局限或平实的收尾，不写口号。
- 引语只截取原文中连续的一段，不拼接。改动标点或分行要在 `小红书图片.md` 的注释里说明。
- 强调色 `==……==` 一张最多一处，留给最关键的原话或数字。
- 全套不超过 18 张。正文图和引语图交替出现，读起来有节奏。

版式的具体数值如下，改版式时连同工具一起改：

| 项目 | 数值 |
| --- | --- |
| 画幅与边距 | 1080 × 1440；左右 104 px，上 120 px，下 96 px |
| 纸色底 | `#F6F3EE`；文字 `#1F1F1F`，页脚 `#6B655D` |
| 强调色 / 引语浅底 | 绿 `#3F5F52` / `#E6EAE3`，蓝 `#3E5C7A` / `#E4EAF1`，砖红 `#9A4A3C` / `#F3E6E1`，赭黄 `#7A5A1E` / `#F3ECDD` |

| 封面图 | 顶部 1080 × 760 插画条，标题 76 px、副标题 38 px，各一行；无插画时标题 84 px；标题上方一条强调色短条 |
| 页脚 | 冬青黑体 28 px，左侧系列名，右侧「n / 总数」 |

#### 全文轮播图

全文版把 `文章_小红书版.md` 的全文排成轮播图，不删减、不改写，读者在小红书里翻图就能读完整篇。

- 封面卡和精简版完全相同，直接取 `小红书图片.md` 的封面卡和顶部插画，所以要先写好 `小红书图片.md` 的封面卡。
- 之后按正文顺序连续排版：小标题（`##` 或小红书版里用 emoji 开头的短行）用宋体粗体 52 px，正文冬青黑体 36 px、行距 62，引用段用宋体常规体加左侧色条，表格逐行转成「列名：内容」的段落，正文配图按原比例放进页面并带说明。段落排不下就接到下一张，页底不留孤行。
- 跳过一级标题和紧跟其后的斜体副标题，因为封面卡已经有了；分隔线和 emoji 去掉，其余文字全部保留，参考出处也保留。
- 全套超过 18 张时，工具自动拆成几篇笔记，输出到 `imgs/xhs-full/第1篇/`、`第2篇/`……，每篇开头都放同一张封面卡，正文页尽量平均分。不超过 18 张时直接输出到 `imgs/xhs-full/`。

```bash
python3 <SKILL>/scripts/generate_xhs_slides.py "05_待发表/<主题>" --full --check   # 看会出几张、是否拆篇
python3 <SKILL>/scripts/generate_xhs_slides.py "05_待发表/<主题>" --full           # 出图到 imgs/xhs-full/
```

**什么时候出图：** 两种轮播图都只在用户明确下令时生成。用户说「输出两种轮播图」时，精简版和全文版一起出；只说「轮播图」时只出精简版；用户没提要求时一张都不出，写完文章、交付时也不主动出。出图后检查封面卡、带配图和表格的页面，以及最后一张。

第六节的策展卡片流用于书单和人物思想档案，也用 B 版式。

## 四、微信公众号

`platforms` 列了 `wechat` 才做。资产：`文章.html`、`imgs/cover-wechat.png`（900 × 383）。头条封面要在后台单独设置，生成 HTML 不等于封面已上传。

### 1. 生成 HTML

```bash
npx -y bun <baoyu-markdown-to-html 安装目录>/scripts/main.ts "05_待发表/<主题>/文章.md" --theme qqtech --cite
```

这一步依赖第三方 Skill `baoyu-markdown-to-html`（来自 baoyu-skills，需另行安装），不随本仓库分发。

qqtech 主题参照腾讯科技的排版：内联样式，小标题左侧 4px 蓝色竖条、左对齐，15px 炭黑正文，1.75 倍行距，0.05em 字间距，两端对齐，导语用冰蓝卡片，署名栏中灰，图注居中浅灰，引言用蓝色竖条。外部链接自动转为文末脚注。

在浏览器打开 `文章.html`，全选复制，粘贴进公众号后台草稿箱。

### 2. 推荐合规

- 正文不能有「长按扫码关注」「回复关键词获取」「点击链接」「点击阅读原文跳转」等导流话术，出现一次就会失去公域推荐。
- 不能整篇都是词典式的名词罗列。
- 至少有 1 处 Markdown 表格或高密度的一手物证。
- 去掉百科常识后，作者自己的考据、文献对质、算账或踩坑内容要占 40% 以上。
- 以第一人称的案头研究者或实测者视角写，不虚构朋友或采访。
- 正文配图全部是真实物证，图注写明年代和出处。

## 五、封面

视觉标识：`editorial-handdrawn-v1`，写在文章 frontmatter 的 `cover_style`，质检脚本据此检查双封面。

要求是「AI 只画一张母稿、统一工具排版、中文标题单独排入」。小红书 1440 × 2400 px，宽高比 3:5；公众号 900 × 383 px。

### 1. 画风样板

样板是 [hawthorne-master.png](../assets/style-sample/hawthorne-master.png)，说明见 [画风样板说明](../assets/style-sample/README.md)。想换成自己的画风，设置环境变量 `ZH_LONGFORM_STYLE_SAMPLE` 指向自己的样板图。生成前必须把这张图片**文件本身**作为画风参考传给生图工具；只在提示词里写路径，不等于工具已经收到图片。

可以用 `--palette-ref <图片路径>` 额外传入配色参考图，只借色彩关系，不借画法。

### 2. 插画必须保留的特征

- **线条**：细而略不齐整的铅笔轮廓，有手画的轻微抖动，没有粗黑描边和光滑矢量线。
- **笔触**：密集的彩铅排线塑造形体、光线和质感，树叶、木纹、水面、墙面、衣料和纸张都有手绘细节。
- **颜色**：低到中等饱和度，像彩铅叠出来的柔和色调，光线自然。色组只定主色关系，不能把整张图染成一种颜色，也不用荧光色。
- **人物**：比例接近真人，五官简洁、神态平和。不画卡通大头、圆点眼，也不追求照片写实或细腻的面部塑形。
- **画面**：一个明确的动作，几件文章里真的提到的物件，人物在画面里足够大，环境有生活感。不能把一个小物件放在大片空白中，也不能把插画缩成有框小贴图。
- **符号**：只画文章里有的东西。齿轮、钱币、地球、光点、宇宙圆环、商业图标这类通用符号，除非画面描述里点名，否则不画。比如样板里的星图，对应的是那篇文章开头讲的第谷观星。

常见偏移：卡通扁平人物、粗描边加饱和平涂、矢量插画、油画或照片质感、古版画、厚纸纹和暗角滤镜。

例如「昆仑」题材，可以画一个人扶住直杆、另一个人观察地面影子的具体场景，不要因为标题涉及古代就默认画苍茫雪山和神秘天球轨道。封面注明原创概念插画，不能冒充历史复原图。

### 3. 一张母稿，两种成品

AI 只调用一次，生成一张高分辨率无字插画母稿。推荐母稿约 1:1、宽度至少 1800 px，通栏排入 3:5 成品时插画约占 60% 高度。完整场景填满母稿画幅，不在母稿中额外留出成品标题区。人物头、手、重要工具和主体关系要保留在画内。先看母稿和画风样板是否同类，再排版；母稿不合格时不得靠模板、上色或缩放宣称修复。

| 项目 | 小红书 | 微信公众号 |
| --- | --- | --- |
| 像素尺寸 | 1440 × 2400，3:5 | 900 × 383 |
| 插画安排 | 完整场景等比通栏排在上方，约占 55%～70%，无四周贴图边框 | 整幅场景等比排入一侧，禁止截取固定最右侧或居中片段 |
| 标题 | 下方居中粗宋体，通常 2～4 行 | 另一侧粗宋体，按实际宽度断行，通常 2～5 行 |
| 背景 | 从母稿纯背景边缘取色衔接，不以模板色覆盖或重染插画 | 同左，不能用缩小整个场景制造大块空白 |
| 安全复核 | 原尺寸与 360 × 600 缩略图 | 原尺寸、360 × 153 缩略图与中心 383 × 383 裁切 |

公众号支持左图右文与右图左文，按画面决定。先在母稿里指出实际主体焦点，再验证它落在中心方形安全区。数学坐标检查只证明所填焦点的位置，不证明所填坐标真的是人物或主体；必须打开中心裁切看图。

所有标题逐字沿用对应平台正文 H1，保留标点和中英文空格。这条只管 `cover-xhs.png` 和 `cover-wechat.png` 两张封面图；小红书轮播图的封面卡另有短标题规则，见第三节第 6 小节。小红书已有独立确认的平台标题时沿用该标题。取消「强制两行」与按字数猜字号，按实际字宽测量；放不下就调整断行或版式，不能截字、删空格或擅改题目。

### 4. 制作步骤

统一用 `<SKILL>/scripts/generate_covers.py`，不为每篇另写脚本。它只排版，不画图，也不判断画风。

**第 1 步：写提示词。** 先读正文，想好画面里的具体动作和它跟文章的关系。画风样板由工具自动写进提示词；`--palette-ref` 可选，只作配色参考。

```bash
python3 <SKILL>/scripts/generate_covers.py "05_待发表/<主题>" \
  --prepare --preset blue_gray \
  --scene "一位简化人物在餐桌前操作具体物件，与另一位人物形成明确关系" \
  --relation "用正文里确实涉及的动作解释封面的主题关系"
```

结果是 `imgs/prompts/cover-prompt.md`，开头几行记下标题、色组、参考图、画面和关系，下面是完整提示词。复用历史母稿时用 `--existing-prompt` 导入当时的提示词，不为旧图补编新提示词。

**第 2 步：画一张母稿。** 把提示词和画风样板图片文件一起交给原生 `imagegen`（有配色参考也一并传入），只画一张。先把母稿和样板放在一起比，不是同一类画风就重画，不靠排版补救。

**第 3 步：派生两版。**

```bash
python3 <SKILL>/scripts/generate_covers.py "05_待发表/<主题>" \
  --master "/path/to/generated-master.png" --layout right-art --focal "0.45,0.5"
```

- `--focal` 是看过母稿后定下的主体焦点，0～1 的相对坐标，必须落在公众号中心正方形里。
- 自动断行不理想时，用 `--lines-xhs`、`--lines-wechat` 手动断行，用 `/` 分隔，必须逐字拼回原标题。
- 旧母稿有纯背景的标题预留区时，可用 `--art-box` 去掉，配 `--art-box-note` 说明没裁到人物。纸色接缝明显时，可用 `--background-box` 指定一块无物件的背景，配 `--background-note`。
- 默认不覆盖已有文件。预览用 `--output-dir` 输出到别处，确认要换时加 `--replace` 直接覆盖。

工具会写出两张成品、`imgs/cover.png` 副本、`imgs/cover-source/master.png` 和 `封面设计.md`，并把两张缩略图和公众号中心裁切放到一个临时目录，终端会打印路径。

**第 4 步：看图并记录。** 对照画风样板，打开两张成品、缩略图和中心裁切。在 `封面设计.md` 的「看图记录」里逐项打勾，写一两句实际看到的情况，再把「看图结论」改为「通过」。脚本不会代勾。

**第 5 步：检查。**

```bash
python3 <SKILL>/scripts/verify_covers.py "05_待发表/<主题>"    # 只查文件加 --files-only
```

检查内容：两张成品的尺寸、格式和 sRGB，`cover.png` 和公众号版一致，提示词和母稿存在，`封面设计.md` 记录的标题和正文一致，看图清单全部打勾、有记录、结论为「通过」。标题改过以后，必须重新生成封面。

### 5. 每篇保留的文件

| 文件 | 用途 |
| --- | --- |
| `imgs/cover-xhs.png` | 小红书成品，1440 × 2400 |
| `imgs/cover-wechat.png` | 公众号成品，900 × 383 |
| `imgs/cover.png` | 公众号成品的副本，给 X 和 frontmatter 用 |
| `imgs/cover-source/master.png` | 唯一的母稿 |
| `imgs/prompts/cover-prompt.md` | 母稿提示词 |
| `封面设计.md` | 画面说明、排版参数、看图记录 |

封面标题字体推荐京華老宋体（KingHwa_OldSong），作者特里王（TerryWang）。它可免费商用、可复制传播，但不是开源字体，不得修改字体文件或单独出售，所以本仓库不附带，需要自行下载安装（macOS 放到 `~/Library/Fonts/KingHwa_OldSong.ttf`），也可以用环境变量 `ZH_LONGFORM_TITLE_FONT` 指定任意中文字体。都没有时脚本自动改用系统宋体。

frontmatter 写：`cover_style: "editorial-handdrawn-v1"`、`cover_text: "title-only"`、`cover_image: "imgs/cover.png"`、`cover_xhs: "imgs/cover-xhs.png"`、`cover_wechat: "imgs/cover-wechat.png"`。

交付时链接两张封面。没看过图或仍偏离画风样板的，标「待复核」或「待重做」，不能因为尺寸对就算完成。

旧文章的封面不批量补做，哪篇要重新发布就重做哪篇。

## 六、策展卡片流

适用于名家书单、人物思想档案和认知清单这类「一条一条讲」的文章。每一条是一个单元，配一张书目卡片，同一套卡片既能嵌进公众号正文，也能直接作为小红书轮播图。卡片和第三节的轮播图共用 B 版式：纸色底，一种强调色，宋体书名，冬青黑体正文，没有胶囊标签、阴影和装饰框。

### 1. 每个单元的写法

```markdown
## 01 这本书，让某位作家相信自己也能写作

<!-- card
index: 01
title_zh: 《示例书名》
title_en: Sample Book Title
author_zh: 示例作者
author_en: Sample Author
badge: 某位作家说
quote_zh: 「这里放一句查得到出处的一手原话。」
quote_en: A verifiable first-hand quotation goes here.
image: imgs/01-book.png
-->

![《示例书名》书目卡片 | 出版年份 | 一手信源](imgs/cards/card_01_wechat.png)

200～300 字的短手记：他在什么时候遇到这本书，解决了什么具体的困惑。

—————❖—————
```

- 小标题写清楚「谁、做了什么、得到什么」，不写格言。
- `quote_zh`、`quote_en` 只放真实的一手原话，查不到原话就留空。
- `image` 用真实书影或物证照片，没有就留空，卡片会只排文字。
- 单篇 9～15 个单元，小红书一篇最多 18 张。
- 卡片数据也可以放在文章目录的 `cards.json` 里，字段相同。

### 2. 卡片样式

| 项目 | 小红书 | 公众号 |
| --- | --- | --- |
| 画幅 | 1080 × 1440 | 1080 × 810 |
| 书影 | 上方，最大 420 × 420，1 px 浅灰描边 | 左侧，最大 380 × 600，1 px 浅灰描边 |
| 文字 | 书名宋体粗体 60 px；英文书名、作者 30 px 灰字；标签 30 px 强调色；中文引语宋体 44 px；英文原话 28 px 灰字 | 同样的层级，字号缩小到 44、24、24、34、22 px |
| 其他 | 左上章节号与色条，底部系列名与页码 | 文字列顶部章节号与色条 |

强调色用 `--palette` 选：`green`、`blue`、`red`、`ochre`，和轮播图的四组一致。旧名 `warm_paper`、`cream`、`sage`、`ink_blue` 仍可用，分别对应 red、ochre、green、blue。排不下时工具报错，不缩小字号。

### 3. 出图

和轮播图一样，必须等文章定版、审读通过，并且用户明确要出图时才运行：

```bash
python3 <SKILL>/scripts/generate_curated_cards.py --article "05_待发表/<主题>" --palette green --series "系列名"
python3 <SKILL>/scripts/generate_curated_cards.py --article "05_待发表/<主题>" --mode xhs      # 只出小红书
python3 <SKILL>/scripts/generate_curated_cards.py --article "05_待发表/<主题>" --mode wechat   # 只出公众号
python3 <SKILL>/scripts/generate_curated_cards.py --demo                                        # 演示样张
```

输出到 `imgs/cards/card_XX_xhs.png` 和 `card_XX_wechat.png`。短手记直接作为公众号正文，也可以贴进小红书笔记文案。
