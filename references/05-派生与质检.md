# 派生平台版本与质检

规则：`<SKILL>/rules/平台与封面.md` 第一至四节。只做 frontmatter `platforms` 里列出的平台。

## X（每篇都有）

`文章.md` + `caption.md`。caption 写 1~3 段，讲清核心主张和读者能得到什么，不写正文没有的事实。

## 小红书（`platforms` 含 `xhs`）

1. 复制 `文章.md` 为 `文章_小红书版.md`，`caption.md` 为 `caption_小红书版.md`。
2. 按第三节第 1 小节的例外改写：标题 20 字以内、每段 2~3 句、可用 emoji 标记小节、可轻度加粗、结尾可设讨论话题、话题标签 3~4 个。
3. 按第三节第 3 小节的敏感词表逐类替换，删掉所有外链，出处改成纯文本。
4. 按第三节第 4 小节防洗稿：开头给出博主自己的视角和判断。

## 公众号（`platforms` 含 `wechat`）

```bash
npx -y bun <baoyu-markdown-to-html 安装目录>/scripts/main.ts "05_待发表/<主题>/文章.md" --theme qqtech --cite
```

再对照第四节第 2 小节的推荐合规检查一遍：没有导流话术、至少一处表格或高密度一手物证、作者自己的考据占 40% 以上。

## 质检

```bash
<SKILL>/scripts/verify_article.sh "05_待发表/<主题>"            # 标准
<SKILL>/scripts/verify_article.sh --xhs "05_待发表/<主题>"      # 列了 xhs 时
<SKILL>/scripts/verify_article.sh --wechat "05_待发表/<主题>"   # 列了 wechat 时
```

红色错误先修好。脚本不能代替事实核查、译名、视觉质量和独立审读。涉及模型、价格或软件界面的教程，发布当天按第一节第 3 小节再复核一次。

质检通过后进入 `07-交付与发布.md`。轮播图只在用户下令时做，见 `06-轮播图与卡片.md`。
